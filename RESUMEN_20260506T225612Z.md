## Qué es este proyecto

Herramienta para evaluar proyectos semestrales de DSY1103 (Full Stack I). Los alumnos
construyen sistemas con 10+ microservicios Spring Boot. El sistema:
1. Clona los repos GitHub de los alumnos
2. Compila cada uS con Maven/Gradle dentro de un contenedor Docker
3. Levanta los contenedores en los puertos definidos en `application.properties`
4. Corre escenarios de prueba (fácil/mediano/difícil) definidos en YAML
5. Reporta pass/fail por step en tiempo real via SSE

## Cómo retomar

### Prerrequisitos en la máquina
- Docker instalado y corriendo
- Python 3.12+
- pip3

### Instalar dependencias Python (solo primera vez)
```bash
pip3 install -r backend/requirements.txt --break-system-packages
```

### Construir la imagen Docker (solo primera vez o si cambió el Dockerfile)
```bash
docker build -f Dockerfile.spring-runner -t dsy1103-spring-runner:latest .
```

### Levantar el backend
```bash
cd /home/toopazo/Dropbox/tomas/repos_git/dsy1103_frontend
uvicorn backend.main:app --reload --port 8000
```

### Validar un servicio completo (clone → build → run → health)
```bash
python3 backend/validate.py \
  --repo https://github.com/toopazo/dsy1103_bibliotecaduoc \
  --port 8081
```

### Correr escenarios directamente desde Python
```bash
python3 -c "
import asyncio, sys
sys.path.insert(0, 'backend')
import scenario_runner

async def main():
    async for e in scenario_runner.run_evaluation('test_biblioteca', 'easy'):
        print(e)

asyncio.run(main())
"
```

### Correr escenarios via API (con backend corriendo en :8000)
```bash
curl -N http://localhost:8000/api/evaluate/test_biblioteca/easy
```

## Decisiones de diseño tomadas
- **Java directo en Docker** (no se genera docker-compose por servicio): el evaluador
  usa el Docker Python SDK para arrancar contenedores programáticamente
- **Un solo puerto por servicio**: definido en `application.properties` del alumno,
  leído por el profe y puesto en el `groups/*.yaml`
- **Contexto de variables persiste en toda la sesión**: `{{libro_id}}` extraído en
  el step 1 está disponible en todos los steps siguientes, incluso entre escenarios
- **No abortar en fallo**: el evaluador continúa aunque un step falle, reporta todo
- **Secretos opcionales**: si el alumno gitignoreó sus credenciales, el profe los
  entrega por separado y el sistema los inyecta antes del build
