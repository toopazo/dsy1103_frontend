## Problema raíz resuelto: NeonDB + Docker

El SSL handshake de NeonDB se colgaba desde contenedores Docker bridge porque los paquetes TLS grandes (certificado Azure) se fragmentaban y los fragmentos se perdían. Solución: `network_mode="host"` en todos los contenedores de servicios.

Pasos para levantar todo:
```bash
# Backend
cd backend && uvicorn main:app --port 8000 &

# Frontend
cd frontend && npm run dev &
# → http://localhost:3000
```

El servicio se reinicia vía UI (Clonar y Levantar) o directamente:
```bash
curl -X POST http://localhost:8000/api/services \
  -H "Content-Type: application/json" \
  -d '{"name":"biblioteca-service","repo":"https://github.com/toopazo/dsy1103_bibliotecaduoc","port":8081,"env_vars":{"SPRING_DATASOURCE_URL":"jdbc:postgresql://ep-plain-rain-a8wzncnl-pooler.eastus2.azure.neon.tech/neondb?sslmode=require&socketTimeout=30&connectTimeout=30"}}'
```
